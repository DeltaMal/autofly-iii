# Reference: the Python email importer (`ff3_email_importer`) being ported

This is the behaviour Phase 3 must reproduce. The Python repo is private and local to the owner; this document and the golden fixtures are the contract.
- **Golden fixtures:** [`ext/tests/fixtures/fnb-email/golden.json`](../tests/fixtures/fnb-email/golden.json), generated by `scripts/export_golden.py` in the Python repo. The generator runs the real Python code over anonymised fixture emails and test strings.

## 2. Gmail provider

- **Scope:** only `https://www.googleapis.com/auth/gmail.modify` (read + label; never delete).
- **Python OAuth flow:** a Desktop client with `InstalledAppFlow.run_local_server`. The token JSON includes `refresh_token`, `client_id`, `client_secret` and `token_uri`. Tokens are refreshed in memory and never re-saved. The consent screen must be **In production**, or refresh tokens expire after 7 days.
- **Query** (`build_query`): parts joined by spaces:
  1. `from:(a OR b)`, or `from:a` for one sender;
  2. `(<extra query>)`, if set;
  3. `after:<epoch seconds>`;
  4. `-label:<search-name>` for the **imported** label only.
  - Epoch seconds avoid Gmail reading `YYYY/MM/DD` as Pacific midnight.
  - Label search name = lowercase, with `/` and spaces turned into `-` (`Firefly/Imported` → `firefly-imported`).
  - `since` = `now − lookback_days` (or a CLI `--since`).
  - Example: `from:inContact@fnb.co.za after:1790812800 -label:firefly-imported`.
- **List:** `messages.list(q, maxResults=500)`, following `nextPageToken`.
- **Fetch:** `messages.get(format=raw)`, base64url-decoded, `received_at` = `internalDate` ms (UTC). The PHP port uses `format=full` instead (see [03](03-email-import.md)), and the golden fixtures prove the two give the same text.
- **Labels:**
  - The label list is cached, with names lowercased.
  - Labels being added are created when missing (`labelListVisibility: labelShow`, `messageListVisibility: show`). Labels being removed are skipped when missing.
  - Applied with `messages.batchModify` in chunks of 1000.
- **Multiple mailboxes:** each has its own token, and failures are isolated per mailbox. The same alert in two mailboxes has the same external id, so it is imported once.

## 3. FNB email template (`banks/fnb.py`, `banks/base.py`, `text.py`)

### Sender and authenticity
- **`matches`:** the lowercased `From` address is in `senders = ("inContact@fnb.co.za",)`, compared case-insensitively.
- **`is_authentic`:** always true when `require_authenticated` is false. Otherwise `sender_authenticated(auth_results, "fnb.co.za")`:
  - **only the first (topmost) `Authentication-Results` header** is used, because lower ones could be supplied by the sender;
  - split it on `;`, then strip and lowercase each clause;
  - a clause passes if it starts with `dkim=pass`, `spf=pass` or `dmarc=pass` **and** matches `[@=.]` + escaped domain + `(?![\w.-])` (case-insensitive).
- In the pipeline, an authenticity failure makes the email **unmatched** (reason text), never imported.

### Text normalisation (`text.py`)
- **`normalise_line`:**
  1. replace `[☺\U0001f642\U0001f60a\U0001f600]` with `:-)`;
  2. replace `[\xa0 -​  　﻿•●\xb7\t\r\f\v]` with a space;
  3. collapse 2+ spaces to one;
  4. strip.
- **`normalise_text`:** `normalise_line` on each line, drop empty lines, join with `\n`.
- **`html_to_text`:**
  1. BeautifulSoup `html.parser`;
  2. remove `script`, `style` and `head`;
  3. insert `\n` before and after every `br p div li tr table h1 h2 h3 h4 ul ol`;
  4. `get_text()` (entities decoded);
  5. `normalise_text`.
- **`extract_bodies`:** HTML part first (as text), then `text/plain` (`normalise_text`). Duplicates dropped. The order matters: the first body that yields segments wins.

### Splitting a body into notifications
```python
_PREFIX   = re.compile(r"FNB\s*:-?\)\s*")                       # "FNB :-)", "FNB:-)", "FNB:)"
_WHEN_END = re.compile(r"\b\d{1,2} ?[A-Z][a-z]{2} \d{1,2}:\d{2}\b")
```
- For each prefix match, the chunk runs to the next prefix (or the end).
- Turn `\n` into spaces, then cut right after the first `_WHEN_END` match. With no match, keep only the chunk's first line.
- Then `normalise_line`, and keep the segment if it is not empty.
- **No segments in any body:**
  - if the joined bodies match `FNB Transaction declined` or `Helping safeguard your account` (case-insensitive) → **ignored** (first 300 characters);
  - otherwise → **unmatched** (first 1000 characters, or the subject).
- **The subject is never parsed.**

### Rules (tried in order with `search`; first match wins)
```python
_AMOUNT = r"R ?(?P<amount>\d[\d, ]*\.\d{2})"
_ACCOUNT = r"(?P<account_type>(?:(?! from ).)+?) ?(?:a/c)?\.\.(?P<account>\d+)"
_CARD = r"using card\.\.(?P<card>\d+)\."
_AVAIL = r"(?: Avail R ?(?P<avail>-?\d[\d, ]*(?:\.\d{2})?)\.)?"
_REF = r"(?: Ref\.(?P<ref>.*?)\.)?"
_WHEN = r" (?P<day>\d{1,2}) ?(?P<month>[A-Z][a-z]{2}) (?P<time>\d{1,2}:\d{2})"
_TO_ACCOUNT = r"(?P<to_type>(?:(?! @ ).)+?) ?(?:a/c)?\.\.(?P<to_account>\d+)"

card_reserved  rf"^{_AMOUNT} reserved for purchase(?: @ (?P<merchant>.+?))? from {_ACCOUNT} {_CARD}{_AVAIL}{_WHEN}$"   withdrawal  tags (fnb-reserved,)
card_reversal  rf"^REVERSAL of {_AMOUNT} for (?P<reason>.+?) from {_ACCOUNT} {_CARD}{_AVAIL}{_WHEN}$"                deposit     tags (fnb-reversal,)
paid_from      rf"^{_AMOUNT} paid from {_ACCOUNT} @ (?P<channel>.+?)\.{_AVAIL}{_REF}{_WHEN}$"                          withdrawal  tags (fnb-payment,)
paid_to        rf"^{_AMOUNT} paid to {_ACCOUNT} @ (?P<channel>.+?)\.{_AVAIL}{_REF}{_WHEN}$"                            deposit     tags (fnb-received,)
transfer       rf"^{_AMOUNT} t/fer from {_ACCOUNT} to {_TO_ACCOUNT} @ (?P<channel>.+?)\.{_AVAIL}{_REF}{_WHEN}$"        transfer    tags (fnb-transfer,)
electricity_token  r"Elec Amt:.*Credit Token:"     (not anchored)  ignored
payment_link       r"^Payment Link created\b"                       ignored
```
- No rule matches → the segment is **unmatched**. This includes ATM `withdrawn from …`, which has no rule yet.
- A `ValueError` while building the transaction also makes the segment unmatched. Causes: bad amount, impossible date such as `30Feb`, unknown month.
- An email can produce transactions **and** unmatched segments. Its outcome is then `unmatched`.

### Building a transaction (`FnbTemplate._transaction`)
Every group is `.strip()`ped; missing groups become `""`.

| Field | Rule |
|---|---|
| `amount` | `parse_amount`: drop `,` and spaces, then `Decimal`. Always positive. |
| `balance_after` | `parse_amount(avail)` or None |
| `occurred_at` | `infer_datetime(day, month, time, received_at, tz)`: month = first 3 letters, case-insensitive. Try the received year (in local tz), then the year before. Take the first **valid** date `≤ received_local + 1 day`. Otherwise `ValueError`. |
| `account_ref` | `account` digits |
| `account_label` | `"{account_type} ..{account}"`, e.g. `FNB card ..100100`, `Smart Account ..300300` |
| `card_ref` | `card` or None |
| `counter_account_ref` | `to_account` or None (transfers only) |
| `counterparty` | transfer: `"{to_type} ..{to_account}"`. card_reserved: merchant or `Card purchase`. card_reversal: `Card reversal` (the reason is never used). paid_from/paid_to: ref, else channel, else `FNB`. |
| `description` | transfer: `"Transfer from {account_label} to {counterparty}"`; otherwise the counterparty |
| `tags` | config tags + rule tags, + `fnb-eft` only if the rule is `paid_from` and channel.lower() == `eft`. Duplicates removed, order kept. |
| `raw_text` | `"FNB :-) " + segment` |
| `signed_amount` | +amount for a deposit; −amount for a withdrawal **and a transfer** |

**External id (must stay byte-identical; it is the dedup key against everything already imported):**
```
key = "|".join(rule, account, card or "", f"{amount:.2f}", counterparty.upper(),
               occurred_at.strftime("%Y-%m-%dT%H:%M")  # local time
               , "" if balance is None else str(balance))
# repeats of the same key inside ONE email: key + "|1", "|2", ...
external_id = "fnb-" + sha256(key.encode("utf-8")).hexdigest()[:32]      # 36 chars
```
- **`str(Decimal)`:** keeps written cents (`1234.50`), drops leading zeros (`0123` → `123`), keeps a sign (`-1234.50`). The PHP port must copy this; the golden file has vectors for it.
- **`counterparty.upper()`:** full Unicode case mapping (`Straße` → `STRASSE`). In PHP, `mb_strtoupper($s, 'UTF-8')` does full mapping on PHP ≥ 7.3. Verify it with the golden `unicode_upper_counterparty` vector.

## 4. Account resolution (`accounts.py`)

`resolve(bank_id, partial, use_default=True)` returns `(account_id | problem, not_found flag)`:
1. **Explicit mapping** `banks.<bank>.accounts[partial]`. If Firefly accounts are known and the id isn't among them, fail with "does not exist".
2. **Number match** (only when the Firefly account list is available):
   - strip non-digits from both sides;
   - candidates are **active** asset and liability accounts with an account number whose digits `startswith(partial)` (or `endswith` in suffix mode) and are at least as long;
   - exactly 1 → that account;
   - more than 1 → fail "matches several accounts". **Never guess.**
3. **`default_account_id`**, only when `use_default` (it must exist too).
4. **Otherwise:** Firefly unavailable → fail "not available". Available → fail "no active … account whose number starts/ends with …", with **`not_found = True`**.

Spaces in Firefly account numbers are ignored (`1001 0012 345` matches `100100`).

## 5. Pipeline and state (`pipeline.py`, `state.py`)

**SQLite tables:**
- `messages(mailbox_id, message_id PK, outcome, status, label_synced, subject, received_at, run_id, updated_at)`
- `transactions(external_id PK, mailbox_id, message_id, status, attempts, account_id, run_id, error, payload, updated_at)`
- `message_transactions(mailbox_id, message_id, external_id PK)`

**Transaction statuses:**
- `pending → submitted → imported`; a miss goes back to pending, then `failed` after `max_attempts`.
- `unmapped` = no account match yet. It is re-checked **every run**, and becomes pending once resolvable.

**Message status** (derived, checked in this order):
1. outcome unmatched → `unmatched`;
2. no linked transactions → `ignored`;
3. all imported → `imported`;
4. any failed → `failed`;
5. otherwise → `pending`.

`imported` and `ignored` are final. Any status change resets `label_synced=0`.

**One run:**
1. With `--retry-failed`: failed transactions → pending (attempts 0); failed messages → pending.
2. **Per mailbox** (an exception is logged, the other mailboxes continue):
   - search;
   - for each id, **skip it if it has a status other than `unmatched`**; new and unmatched messages are fetched and parsed;
   - parse with the first bank template whose `matches()` is true;
   - authenticity failure → unmatched; parser exception → unmatched; no template → unmatched;
   - record the message, upsert transactions (**first sighting wins**, plus a link row);
   - commit after every message.
3. **Load:** gather every `pending` or `unmapped` transaction (all mailboxes) and resolve accounts using the transfer matrix (§7).
   - Unresolved → `unmapped` with the problem text.
   - Pre-check each external id against Firefly: anything already there → `imported`, not uploaded.
4. **Upload** to FIDI, then verify each id through the Firefly API. *(The PHP port stores synchronously instead; see [03](03-email-import.md).)*
5. Refresh message statuses.
6. **Sync labels,** only for mailboxes that loaded this run and only for messages with `label_synced=0`:
   - `imported` → add the imported label, remove the unmatched label;
   - `unmatched` → add the unmatched label;
   - `pending`, `failed` and `ignored` → no label.
   - A failed sync is retried next run.
- **Unmatched emails** are saved for review as `data/unmatched/<mailbox>/<id>.eml/.txt`. The fork shows them in the activity UI instead.
- **Dry run:** parse and resolve read-only; nothing committed, no upload, no labels.
- **Lock:** `data/run.lock` (`O_EXCL`; stale after 2 h), so only one run happens at a time.

## 7. How rows become Firefly transactions

Fields Python sends (through the FIDI CSV):
- `external_id`
- date = occurred_at local `Y-m-d H:i:s`
- signed amount from the account's view
- description
- account id
- opposing name (counterparty) or opposing id (own-account transfer)
- currency
- tags
- `internal_reference` = `card..<card_ref>` (or empty)
- notes (§6)
- import tag `Email import <date>`
- rules: on; webhooks: on

**Transfers:** the source side is resolved with the default allowed; the target side with `use_default=False`.

| Source resolves | Target resolves | Booked as |
|---|---|---|
| yes | yes | One row from source to target. Firefly makes asset→asset a **transfer** and asset→liability a **withdrawal**, with the liability as destination. |
| yes | `not_found` | Withdrawal from the source, opposing name = counterparty (e.g. `home loan ..040400`) |
| `not_found` | yes | **Deposit** on the target, opposing name = the source `account_label` |
| anything else (ambiguous, broken mapping, Firefly down) | | `unmapped`, problems joined with `; ` |

Non-transfers need only the source account; otherwise they are `unmapped`.

## 8. Behaviour locked in by the Python tests (reproduce all of them)
- Merchants containing `@`, `,`, `*` or `.`.
- No merchant → `Card purchase`.
- Thousands commas in amount and Avail.
- `Smart Account..N` without `a/c`.
- `paid_to` without Avail.
- Double spaces before the date.
- Reversal without Avail.
- Two bullets → 2 transactions.
- Identical notifications in one email → distinct ids that stay stable on re-parse.
- The HTML and plain parts give the same ids.
- The same alert in two mailboxes gives the same id.
- ATM `withdrawn from` → unmatched, while the other notifications in the same email still import.
- The electricity token, payment link and declined emails are ignored.
- "Your statement is ready" → unmatched.
- A spoofed sender fails authenticity, and `require_authenticated=false` bypasses the check.
- A 31 Dec alert received on 1 Jan is dated in the previous year.
- The split cuts after the time.
- Transfer labels and descriptions follow §3.
- A salary with `FNB:-)` (no space) and `@ Eft` → `paid_to` deposit, with no `fnb-eft` tag.
- **Pipeline:**
  - a second run is idempotent;
  - an email is never re-fetched once its status is final;
  - an unmapped transaction waits, then imports once mapped;
  - a mapping to a non-existent account stays unmapped;
  - a broken mailbox doesn't stop the others;
  - a transaction already in Firefly is not created again.
